Scope: actual Next.js route handlers, services, Prisma calls, pages and tests in this checkout. ## Implemented phases and verification

1. **Catalog/admin phase:** Added `lib/backend-validation.ts`, `lib/catalog-store.ts`, `lib/admin-api.ts`, admin category/product/variant/media routes, DB catalog/resolve routes and home/shop/category/search/product/cart DB-mode integration. Rules: draft first, active category, two-level tree, active priced variant before publish, price history, approved shared media references, server-side same-variant filters. Tests: catalog/inventory PostgreSQL integration, shared-media reference and route denial passed. Blockers: no production identity, media storage or editing UI.
2. **Inventory/order phase:** Added `lib/admin-store.ts`, inventory adjustment/read, order/read, audit/read and dashboard admin routes; extended `lib/database-store.ts` and checkout route to attach signed-in demo orders to profiles atomically; admin page reads DB-mode orders/stats. Rules: no adjustment below reserved, movement/audit in serializable transaction, per-retry stock validation, customer email must match session. Tests: 11 PostgreSQL integration tests passed in four consecutive runs; no destructive migration. Blockers: fulfillment/cancellation/payment/shipping policy and providers.
3. **Account storage phase:** Added `lib/private-fields.ts`, `lib/account-store.ts`, `lib/account-api.ts`, profile/address APIs and one additive `privateDataCiphertext` column migration. The required legacy address fields retain their constraints and receive non-sensitive placeholders on new rows. Tests: 13 PostgreSQL integration tests passed in three consecutive runs after applying only migration 0005 to `flcdecor_test`, including concurrent default-address selection. Blockers: production identity, key management/rotation, legacy plaintext migration and account UI.

## Known risks and next implementation gates

- In-memory demo authentication and single-admin permissions cannot authorize production writes. All admin operations fail closed in production under the current auth adapter.
- Catalog filtering is in application memory after loading published rows. Push filters into indexed SQL and measure at realistic catalog size before launch.
- Database catalog media is represented by CSS fallback artwork. R2 storage, image serving and lifecycle need an approved provider setup.
- New saved addresses use an encrypted payload, but old rows have no ciphertext and cannot be read through the new API. A reviewed backfill/key-rotation plan and production identity are required before live customer data. Operational order transitions still need an approved business policy.
- Checkout payment notifications are durable records, not external deliveries. Production checkout remains disabled regardless of copied demo flags.
